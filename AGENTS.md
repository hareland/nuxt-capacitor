# AGENTS.md

Guide for AI coding agents and humans working in this repo. If `package.json` or a package's own docs disagree with this file, those win; update this file.

## Repo layout

| Path | Purpose |
|---|---|
| `layer/` | The published `nuxt-capacitor` package (Nuxt layer + module). `layer/modules/config.ts` is the module, `layer/utils/` holds pure helpers |
| `playground/` | Nuxt app that consumes the layer via `workspace:*`; used for manual testing (Electron/iOS/Android folders are generated and git-ignored) |
| `.starters/` | Standalone templates (`minimal`, `konsta-ui`) used by `pnpm create nuxt -t github:hareland/nuxt-capacitor/.starters/<name>`. Not part of the workspace; each has its own lockfile |
| `test/` | Vitest tests for `layer/utils` |
| `.release-it*.json` | Release flow (root = GitHub release + changelog, layer = npm publish) |

The list of starters lives in the root `README.md`.

## Working rules

- Run every command from the repo root. Don't `cd` into `layer/` or `playground/`.
- Scope commands with the long form `--filter` (`-f` means `--force` in pnpm), e.g. `pnpm --filter playground dev`.
- Never run `npm install`/`yarn` in a package (exception: `playground/electron`, which is an npm project generated by `@capacitor-community/electron`).
- Starters are installed standalone: after changing one, run `pnpm install` inside it to refresh its lockfile.

## Setup

```bash
pnpm install   # also runs `nuxt prepare` for layer and playground
```

Node version is in `.nvmrc`; pnpm version is pinned via `packageManager`.

## Common commands

| Command | What it does |
|---|---|
| `pnpm dev` | Start the playground (`pnpm dev --host=0.0.0.0` to reach it from a device) |
| `pnpm build` | Prerendered playground build (triggers `cap sync`) |
| `pnpm lint` / `pnpm lint:fix` | ESLint (`@nuxt/eslint`, stylistic) |
| `pnpm typecheck` | `nuxt typecheck layer` |
| `pnpm test` | Vitest |
| `pnpm clean` | Remove playground `node_modules`, `.nuxt`, `.output` |
| `pnpm release` | Release (layer to npm, then GitHub release + changelog) |

## Module conventions (`layer/`)

- The module is configured via `capacitor` in `nuxt.config.ts` (`config`, `output: 'json' | 'ts' | 'js' | 'mjs'`, `autoSync`). `nuxt.config.ts` is the source of truth.
- `capacitor.config.{json,ts,js,mjs}` in a consumer project is **generated** and git-ignored. It is self-contained (no imports from `.nuxt/`) so the Capacitor CLI works on a fresh checkout. Never hand-edit it.
- Keep logic that can be pure in `layer/utils/` and cover it in `test/`; the module file should stay thin glue.
- Dev mode injects `server.url` (devServer URL); production strips it. `webDir` is `.output/public`.
- `layer/package.json` `dependencies` are what every consumer installs: add only what layer code imports. `@capacitor/cli` and `nuxt` are peers.
- After changing module options or dependencies, run `pnpm dev:prepare` to regenerate types.

## Code style

- TypeScript everywhere; avoid `any` (use `unknown` + narrowing or generics).
- Follow the root ESLint config; run `pnpm lint:fix` before finishing.
- Read env vars through `runtimeConfig` in apps; in `nuxt.config.ts` use `process.env`.

## Before finishing a task

1. `pnpm lint`
2. `pnpm typecheck`
3. `pnpm test`
4. `pnpm build` when touching the module, `nuxt.config.ts`, or dependencies

Never commit generated or dependency files: `node_modules/`, `.nuxt/`, `.output/`, `dist/`, `capacitor.config.*`, `ios/`, `android/`, `playground/electron/**` (except `electron/src/**`). Untrack accidents with `git rm -r --cached`.

## Commits and PRs

Conventional Commits (`feat:`, `fix:`, `chore:`, with an optional scope such as `feat(electron):`). Do not add AI attribution trailers or footers to commits or PRs. Changelog and versions are produced by release-it, so don't edit `CHANGELOG.md` or versions by hand.
